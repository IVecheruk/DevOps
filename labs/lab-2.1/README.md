# Задание 2.1 — анализ лога Nginx

[← К списку заданий](../../README.md)

## Цель

Найти IP-адреса, с которых поступило подозрительно много запросов с ответом 404.

## Исходный скрипт: библиотеки и окружение

- `re.findall()` ищет совпадения по регулярному выражению, в примере — IP рядом с кодом 404.
- `collections.Counter` считает, сколько раз встретился каждый IP.
- `requests.post()` отправляет HTTP-запрос с предупреждением в Telegram. `requests` нужно установить отдельно; `re` и `collections` входят в Python.

Для исходного скрипта нужны Python, `requests`, доступный для чтения `/var/log/nginx/access.log`, интернет, токен Telegram-бота и ID чата. В примере из задания адрес Telegram API написан неверно. Формат адреса: `https://api.telegram.org/bot<TOKEN>/sendMessage` ([Telegram Bot API](https://core.telegram.org/bots/api#making-requests)).

## Выполненная часть задания

[Модифицированный скрипт](analyze_logs.py) локально читает [учебный лог](examples/access.log) и считает ошибки 404 по IP. `re` выделяет IP и статус, `ipaddress` проверяет IP, `Counter` ведёт подсчёт. Если ответов 404 **больше 50**, скрипт выводит предупреждение. Telegram для этой демонстрации не нужен.

```bash
git clone https://github.com/IVecheruk/DevOps.git
cd DevOps/labs/lab-2.1
python analyze_logs.py
```

Пример результата:

```text
HTTP 404 responses: 104
Suspicious IP 203.0.113.10: 51 HTTP 404 responses
```

Чтобы проверить свой лог такого же формата, укажите путь к нему в переменной `LOG_FILE` в начале скрипта. Для изменения порога поменяйте `THRESHOLD`.

## Вывод

Выполнена часть функционала исходного задания: анализ лога и обнаружение IP с превышением порога. Учебный лог синтетический; частые 404 — признак для проверки, а не доказательство атаки. Сетевые уведомления в этой версии не реализованы.
