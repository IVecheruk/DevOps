# Лабораторная работа 2.2

[← Все задания](../../README.md)

**Тема:** проверка доступности сайтов средствами Python.

**Условие:** прочитать адреса сайтов из `link.txt`, проверить их доступность и записать результат в `report.txt` в формате `адрес -> статус`, где статус — `Ok` или `Error`.

**Репозиторий:** [IVecheruk/DevOps](https://github.com/IVecheruk/DevOps). **Страница задания:** [labs/lab-2.2](https://github.com/IVecheruk/DevOps/tree/main/labs/lab-2.2).

## 1. Цель работы

Научиться читать текстовый файл, выполнять HTTP-запросы, обрабатывать ошибки и сохранять результаты в другой файл.

## 2. Теоретические сведения

Скрипт использует стандартную библиотеку Python, поэтому устанавливать дополнительные пакеты не нужно.

- `urllib.request.urlopen()` открывает адрес сайта и возвращает HTTP-ответ.
- `urllib.error.HTTPError` обозначает ошибку HTTP, например 404 или 500.
- `urllib.error.URLError` обозначает ошибку обращения к адресу, например проблему с DNS.
- `open()` — встроенная функция для работы с файлами.

Ответы с кодом от 200 до 299 считаются успешными: в отчёт записывается `Ok`. При HTTP-ошибке или проблеме соединения записывается `Error`. Например, 403 означает, что сервер отвечает, но доступ к странице запрещён.

Перенаправления обрабатывает `urlopen`: оценивается конечный ответ. Вызов `urlopen(url, timeout=5)` выполняет GET-запрос и задаёт тайм-аут сетевых операций в 5 секунд.

Документация: [urllib.request](https://docs.python.org/3/library/urllib.request.html), [urllib.error](https://docs.python.org/3/library/urllib.error.html).

### Объяснение кода для защиты

1. **Импорты** подключают функцию открытия сайта и типы сетевых ошибок.
2. **`with open("link.txt", ...)`** открывает список сайтов для чтения. `with` автоматически закрывает файл после работы.
3. **`open("report.txt", "w", ...)`** открывает файл для записи. Режим `"w"` создаёт файл или очищает старое содержимое. `encoding="utf-8"` задаёт кодировку текста.
4. **`for line in links`** перебирает строки входного файла.
5. **`line.strip()`** убирает пробелы по краям и символ переноса строки. Если строка пустая, `continue` переходит к следующей.
6. **`try`** содержит попытку открыть сайт. `with urlopen(...) as response` позволяет получить ответ и автоматически закрыть его.
7. **`200 <= response.status < 300`** проверяет код ответа. Если условие выполнено, переменная `status` получает `"Ok"`, иначе — `"Error"`.
8. **`except HTTPError`** обрабатывает HTTP-ошибку. Она тоже содержит ответ сервера, поэтому `error.close()` закрывает его.
9. **Следующий `except`** обрабатывает ошибки сети, системные ошибки соединения и некорректный адрес. Результат — `"Error"`; цикл продолжает работу со следующим сайтом.
10. **`report.write(f"{url} -> {status}\n")`** записывает адрес и результат. F-строка подставляет значения переменных, а `\n` переводит запись на новую строку.

Краткое объяснение алгоритма:

> Я открываю файл со списком сайтов и файл для результатов. Затем перебираю адреса и пытаюсь открыть каждый через `urlopen`. Если получен успешный HTTP-ответ, записываю `Ok`. Если произошла ошибка — `Error`. Результат каждого запроса сохраняю отдельной строкой в `report.txt`.

## 4. Результаты

Работа проверена на Windows с Python 3.14.3. Для списка из трёх адресов получен отчёт:

```text

https://www.python.org -> Ok
https://example.invalid -> Error
```

Это результат конкретной проверки: состояние внешних сайтов и доступ к ним могут изменяться.

Проверены HTTP-ответы 200/204/404/500, перенаправления, формат результата, пропуск пустых строк, повторы адресов, перезапись отчёта, продолжение после некорректного адреса и отсутствие входного файла. Тесты используют локальный HTTP-сервер и не требуют доступа к внешним сайтам. **Результат: 5 тестов, `OK`.** Тестовый файл нужен для проверки и не является частью основного скрипта.

## 5. Выводы

Создан простой скрипт с одним циклом, который читает адреса из `link.txt` и записывает в `report.txt` строки в требуемом формате. Для решения использованы работа с файлами, HTTP-запросы, условный оператор и обработка исключений.

Скрипт предназначен для списка полных HTTP/HTTPS-адресов. Он проверяет ответ сервера, но не выполняет JavaScript и не входит в учётные записи. Тайм-аут относится к отдельным сетевым операциям; общая проверка может длиться дольше из-за DNS и перенаправлений.
