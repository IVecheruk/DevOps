# Лабораторная работа 2.2

[← Все задания](../../README.md)

**Тема:** проверка доступности сайтов средствами Python.

**Условие:** написать скрипт, который читает адреса сайтов из `link.txt`, проверяет их доступность и сохраняет результат в `report.txt` в формате `адрес -> статус`, где статус — `Ok` или `Error`.

**Репозиторий:** [IVecheruk/DevOps](https://github.com/IVecheruk/DevOps). **Страница задания:** [labs/lab-2.2](https://github.com/IVecheruk/DevOps/tree/main/labs/lab-2.2).

## 1. Цель работы

Автоматизировать проверку списка сайтов: прочитать входной файл, выполнить HTTP-запросы, обработать ошибки и сформировать текстовый отчёт. Обеспечить запуск после клонирования без установки сторонних библиотек.

## 2. Теоретические сведения

Для проверки используется HTTP-запрос `GET`. Тело ответа не читается: программа проверяет полученный статус и закрывает соединение. При перенаправлении проверяется конечный ответ.

В этой работе приняты следующие критерии доступности:

| Результат запроса | Статус в отчёте |
| --- | --- |
| Конечный HTTP-код от 200 до 299 | `Ok` |
| HTTP-ошибка, например 403, 404 или 500 | `Error` |
| Ошибка DNS, соединения, TLS или превышение тайм-аута | `Error` |
| Некорректный адрес или схема, отличная от HTTP/HTTPS | `Error` |

Таким образом, проверяется доступность указанной страницы для скрипта. Например, сервер с ответом 403 отвечает на запрос, но доступ к странице не предоставлен, поэтому результат — `Error`.

Используются модули стандартной библиотеки Python:

| Модуль | Назначение |
| --- | --- |
| `urllib.request` | `Request` создаёт запрос, `urlopen` открывает адрес и обрабатывает перенаправления |
| `urllib.error` | `HTTPError` и `URLError` позволяют обработать ошибки HTTP и сети |
| `urllib.parse` | `urlsplit` выделяет схему и имя хоста |
| `http.client` | `HTTPException` позволяет обработать некорректный HTTP-ответ |
| `pathlib` | Пути к файлам и чтение/запись текста |
| `argparse` | Параметры командной строки |
| `math` | Проверка, что тайм-аут — конечное число |
| `sys` | Вывод сообщений и код завершения программы |

Документация: [urllib.request](https://docs.python.org/3/library/urllib.request.html), [urllib.error](https://docs.python.org/3/library/urllib.error.html).

## 3. Ход выполнения

### 3.1. Файлы задания

```text
labs/lab-2.2/
├── README.md              # условие, отчёт и инструкция
├── check_links.py         # скрипт проверки сайтов
├── link.txt               # входной список адресов
├── report.txt             # результат демонстрационного запуска
└── tests/
    └── test_check_links.py
```

Исходный код: [check_links.py](check_links.py). Входные данные: [link.txt](link.txt). Пример фактического результата: [report.txt](report.txt).

### 3.2. Алгоритм

1. Прочитать `link.txt` в UTF-8. Допускается UTF-8 с BOM, который могут добавлять текстовые редакторы.
2. Удалить пробелы по краям каждой строки, пропустить пустые строки.
3. Проверить формат адреса и выполнить HTTP-запрос с тайм-аутом сетевых операций, по умолчанию 5 секунд.
4. Определить `Ok` или `Error` по результату запроса. Ошибка одного сайта не прерывает проверку остальных.
5. Записать для каждого адреса отдельную строку `адрес -> статус` в `report.txt`.

Порядок и повторяющиеся адреса сохраняются. При каждом запуске отчёт перезаписывается. Входной и выходной файлы должны отличаться. Если исходный файл отсутствует, старый отчёт не перезаписывается.

### 3.3. Окружение и запуск

Нужны Git, Python 3.10 или новее и доступ к сети для проверки внешних сайтов. `pip install` не требуется.

```bash
git clone https://github.com/IVecheruk/DevOps.git
cd DevOps/labs/lab-2.2
python check_links.py
```

Если репозиторий уже клонирован, обновите его командой `git pull` из корня и перейдите в `labs/lab-2.2`. На Linux/macOS при необходимости используйте `python3`, на Windows — `py -3`.

Откройте `report.txt` в текстовом редакторе. Также результат можно посмотреть в терминале:

```powershell
# Windows PowerShell
Get-Content report.txt
```

```bash
# Linux / macOS
cat report.txt
```

По умолчанию `link.txt` и `report.txt` находятся рядом со скриптом. Поэтому из корня репозитория также работает:

```bash
python labs/lab-2.2/check_links.py
```

### 3.4. Собственный список сайтов

Измените `link.txt`, указав по одному полному адресу с `http://` или `https://` на строку:

```text
https://example.com
https://www.python.org
https://example.invalid
```

Адрес без схемы, например `example.com`, будет отмечен как `Error`. Комментарии в списке не предусмотрены: каждая непустая строка считается адресом.

Для других имён файлов и тайм-аута используйте параметры. Следующие команды выполняются из папки задания:

```bash
python check_links.py --input link.txt --output report.txt --timeout 3
python check_links.py --help
```

Относительные пути, явно переданные через `--input` и `--output`, отсчитываются от текущего рабочего каталога. Каталог выходного файла должен существовать.

### 3.5. Автоматические проверки

```bash
python -m unittest discover -s tests -v
```

Тесты запускают временный HTTP-сервер на `127.0.0.1` со свободным портом, поэтому не зависят от доступности внешних сайтов. Сетевые сбои дополнительно моделируются подменой `urlopen`.

## 4. Результаты

Работа проверена на Windows с Python 3.14.3. При запуске 26 сентября 2026 года с включённым в репозиторий `link.txt` получен файл `report.txt`:

```text
https://example.com -> Ok
https://www.python.org -> Ok
https://example.invalid -> Error
```

В терминале выведена сводка:

```text
Проверено: 3; Ok: 2; Error: 1
```

Программа также выводит путь к созданному отчёту. Это результат конкретного запуска: доступность внешних сайтов может измениться или зависеть от сети пользователя.

**Автоматические проверки: 9 тестов, результат `OK`.** Проверены ответы 200/204/404/500, перенаправления на успешную и отсутствующую страницу, некорректные адреса, сетевые ошибки, формат отчёта, порядок и повторы адресов, пустой файл, защита входного файла, отсутствие списка адресов, тайм-аут и запуск из другого каталога без сторонних библиотек.

Код завершения `0` означает, что отчёт успешно сформирован, даже если некоторые сайты получили `Error`. Код `1` означает ошибку работы с файлами или недопустимое значение тайм-аута.

## 5. Выводы

Разработан Python-скрипт, выполняющий условие задания: адреса читаются из `link.txt`, доступность проверяется HTTP-запросами, результаты записываются в `report.txt` в требуемом формате. Ошибка отдельного сайта не останавливает обработку списка.

Проверка отражает состояние адресов на момент запуска. Скрипт не выполняет JavaScript, не входит в учётные записи и не оценивает содержимое страницы. Тайм-аут ограничивает отдельные сетевые операции, а не общую длительность проверки: разрешение DNS и цепочка перенаправлений могут увеличить время ожидания.
