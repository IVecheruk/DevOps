**Тема:** проверка изменений веб-страниц при повторном обходе.

**Условие:** прочитать адреса страниц из `link.txt`, проверить, изменилось ли их содержимое с прошлого обхода, и сохранить результат в `report.txt`.

**Репозиторий:** [IVecheruk/DevOps](https://github.com/IVecheruk/DevOps). **Страница задания:** [labs/lab-2.4](https://github.com/IVecheruk/DevOps/tree/main/labs/lab-2.4).

## 1. Цель работы

Научиться загружать веб-страницы, сохранять сведения об их содержимом и сравнивать результаты двух запусков программы.

## 2. Теоретические сведения

Для каждой страницы вычисляется **SHA-256-хеш** её содержимого — строка из 64 шестнадцатеричных символов. Если на следующем обходе хеш совпадает с предыдущим, полученные байты страницы не изменились. Если хеш отличается, программа отмечает изменение. Хеш нужен для сравнения; это не шифрование страницы и не описание того, *что именно* поменялось.

Предыдущие хеши хранятся в локальном `hashes.json` в виде соответствия «адрес → хеш». Этот файл создаётся автоматически при первом запуске и позволяет сравнить страницы при следующем запуске. В Git он не публикуется, чтобы после клонирования первый обход был действительно первым.

Используются только модули стандартной библиотеки Python:

| Модуль | Назначение |
| --- | --- |
| `urllib.request` | `urlopen()` загружает страницу по HTTP/HTTPS |
| `urllib.error` | `HTTPError` и `URLError` позволяют обработать ошибки запросов |
| `hashlib` | `sha256()` вычисляет хеш байтов страницы |
| `json` | `loads()` и `dumps()` читают и записывают сохранённые хеши |
| `pathlib` | `Path` читает и записывает файлы, проверяет наличие `hashes.json` |

Справка: [urllib.request](https://docs.python.org/3/library/urllib.request.html#urllib.request.urlopen), [hashlib](https://docs.python.org/3/library/hashlib.html#hashlib.sha256), [json](https://docs.python.org/3/library/json.html).

После каждого запуска откройте `report.txt` в текстовом редакторе. На Windows PowerShell можно выполнить `Get-Content report.txt`, на Linux/macOS — `cat report.txt`.

### Как работает скрипт

1. `Path("link.txt").read_text(...).splitlines()` считывает список адресов.
2. Если `hashes.json` существует, `json.loads()` загружает хеши предыдущего обхода; иначе создаётся пустой словарь.
3. Цикл проходит по адресам. `strip()` убирает пробелы; `continue` пропускает пустую строку или комментарий.
4. `urlopen(url, timeout=10)` получает страницу, а `response.read()` возвращает её содержимое **в байтах**. `hashlib.sha256(...).hexdigest()` превращает его в хеш.
5. Хеш сравнивается с предыдущим значением для этого же адреса. Результат записывается в `report.txt` одной строкой на страницу.
6. После обхода `json.dumps()` сохраняет новые хеши в `hashes.json` для следующего запуска.

| Статус | Значение |
| --- | --- |
| `NEW` | Страница успешно получена, но прежнего хеша для адреса нет |
| `OK` | Хеш совпадает с прошлым обходом |
| `CHANGED` | Хеш отличается от прошлого обхода |
| `ERROR` | Страницу не удалось получить или адрес некорректен |

При `ERROR` прежний хеш сохраняется: неудачный запрос не считается изменением страницы. Результат очередного обхода перезаписывает `report.txt`; поэтому для защиты удобно открыть его после первого запуска, затем запустить скрипт ещё раз.

Краткое объяснение для защиты:

> Я читаю список адресов и загружаю каждую страницу. Вычисляю хеш полученных байтов и сравниваю его с хешем из предыдущего запуска. Если прежнего значения нет — `NEW`, если совпало — `OK`, если отличается — `CHANGED`. Ошибка запроса даёт `ERROR`. Отчёт сохраняю в `report.txt`, а успешные хеши — в `hashes.json`.

## 4. Результаты

На **26 сентября 2026 года** два последовательных запуска с включённым [link.txt](link.txt) дали:

| Адрес | Первый обход | Второй обход |
| --- | --- | --- |
| `https://example.com` | `NEW` | `OK` |
| `https://example.invalid` | `ERROR` | `ERROR` |

Фактический [report.txt](report.txt) после второго запуска:

```text
https://example.com -> OK
https://example.invalid -> ERROR
```

После свежего клонирования `hashes.json` отсутствует, поэтому первый запуск снова покажет `NEW` для успешно загруженной страницы. Доступность внешнего сайта и его содержимое могут измениться, тогда результат будет другим.

Проверка без внешней сети:

```bash
python -m unittest discover -s tests -v
```

**Результат: 2 теста, `OK`.** На локальном HTTP-сервере проверена последовательность `NEW` → `OK` → `CHANGED` → `ERROR`, сохранение последнего успешного хеша при ошибке, пропуск комментария и пустой строки, а также отсутствие выходных файлов при отсутствующем `link.txt`.

## 5. Выводы

Создан скрипт, который обходит адреса из файла и сообщает, изменились ли страницы со времени последнего успешного получения. Задание выполнено без сторонних библиотек и с небольшим числом шагов, которые можно объяснить на защите.

Сравниваются байты HTML-ответа целиком. Даже изменение времени, рекламы или служебного блока в HTML даст `CHANGED`, хотя видимая часть страницы могла остаться прежней. Скрипт не выполняет JavaScript и не показывает различия между версиями страницы. Удаление `hashes.json` сбросит историю сравнений: следующий успешный обход будет отмечен как `NEW`.
